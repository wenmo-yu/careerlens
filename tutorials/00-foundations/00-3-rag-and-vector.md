# 00-3 · RAG 与检索：怎么从一堆材料里找证据

**这一课你能做到**：用大白话解释向量检索在做什么；分清「关键词相同」和「意思接近」两条线索；明白「检索到了」也不等于「能支持结论」。

**前置**：只有浏览器。建议先读 [00-2](00-2-prompt-and-evidence.md)。

**用时**：约 20 分钟，动手约 5 分钟。

---

## 检索像在档案柜里选资料

想象你有一个档案柜，里面全是你的材料卡。有人问「我适合 AI 岗位吗」，你不会把整个柜子都塞给他，而是先挑出相关的几张。这就是**检索**。

RAG（检索增强生成）就是：**先检索出相关材料，再让 AI 基于这些材料回答**。这样回答就有依据，而不是凭空编。

<details>
<summary>一张图（文字版在下面）</summary>

```mermaid
flowchart LR
    Q[问题] --> R[检索档案柜]
    R --> E[相关证据卡]
    E --> M[AI 基于证据回答]
    M --> A[带依据的回答]
```

**文字版**：问题先触发检索，从材料堆里挑出相关证据卡，AI 只基于这些卡回答，于是答案带依据。

</details>

## 两条找材料的线索

从档案柜里找卡片，有两种完全不同的方式：

| 线索 | 怎么找 | 优点 | 盲点 |
| --- | --- | --- | --- |
| 关键词匹配 | 字面对上就算命中 | 精确、可控 | 换个说法就找不到 |
| 意思接近（向量检索） | 把文字变成一组数字（坐标），意思接近的坐标也接近 | 能找到换过说法的材料 | 可能找来「看着相关、其实不支持」的卡 |

**向量**就是把一段文字变成一组数字。你可以把它想成给文字拍一张「意义坐标」：意思相近的话坐标挨得近，于是可以按距离找资料，而不必字面一模一样。

## 动手：手工比较两种找法

还是林澈的三张卡：

| 卡片 | 内容 |
| --- | --- |
| A | 「用 Python 做过课程项目」 |
| B | 「收藏了 Kubernetes 教程」 |
| C | 「课程项目只在本机演示」 |

现在的问题是：**「有没有做过编程相关的实践？」**

**只用关键词**：问题里有「编程」，三张卡都没有「编程」二字——一张都找不到。这就是关键词的盲点。

**按意思接近**：

1. 哪张卡和「编程实践」意思最接近？（提示：Python 是一种编程语言）
2. 检索系统可能会把哪张卡也捞进来，但其实不支持结论？（提示： Kubernetes 也是技术名词，容易被误当成相关）

<details>
<summary>参考答案</summary>

- 最相关的是 **A**（用 Python 做过课程项目）——它直接支持「做过编程实践」。
- 容易被误捞的是 **B**（收藏 Kubernetes 教程）：它含有技术名词，字面上「像」相关，但收藏不等于做过实践，**不能支持结论**。
- C（只在本机演示）能提供补充信息：实践范围有限，不能据此说「部署上线经验」。

</details>

**这就是关键一课**：检索到一张卡，只说明它「相关」，不等于它「支持你的结论」。相关和支持是两回事。所以 CareerLens 在检索之后还有一步**引用核验**：把真正能支持的证据留下，把「只是相关」的丢掉。

## 两种线索合起来用

只看关键词会漏，只看意思会误捞。实际系统通常两路都做，再合并：

<details>
<summary>一张图（文字版在下面）</summary>

```mermaid
flowchart LR
    Q[问题] --> K[关键词检索]
    Q --> V[语义检索]
    K --> F[合并两路结果]
    V --> F
    F --> X[精挑: 留下真正支持的]
    X --> A[带引用的回答]
```

**文字版**：问题同时走关键词和语义两路检索，结果合并后再精挑一次，留下真正支持结论的证据，才交给回答。

</details>

项目里，两路结果用一个叫 RRF 的规则合并，再精排一次；提问时还能切换 `rag`（只找证据）、`wiki`（找整理好的主题页）、`hybrid`（两者都要）三种模式，**切换不用重建任何东西**。这些词会在往后篇章里逐一出现，现在只要知道「有多种找法、还会合并和精挑」。

> [!NOTE]
> 本课全部是**纸面模拟**：卡片和判断都写在教程里，不涉及在线推理。真实的模式切换练习放到 [01](../01-quickstart.md) 的选做和 [04](../04-retrieval-agent.md)。
