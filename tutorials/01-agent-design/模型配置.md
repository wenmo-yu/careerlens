# 模型配置 · 从 Demo 切换到兼容 API 或本地模型

上一课让程序按名字调用一个工具。取回原文后，轮到答复节点组织回答。先用一条合成资料跑出 Demo 对照，再按自己的环境选做兼容 API 或本地模型。跑过 Demo 就可以进入下一课，后面的关卡测试也都能用 Demo。

## 本课先懂的技术

**模型提供器（provider）**是后端里负责调用模型的一层。在 `backend/app/graph/career.py` 搜 `get_llm_provider("answer")` 看调用，在 `backend/app/llm/provider.py` 搜 `def get_llm_provider` 看定义。这个函数为答复角色选择实现。Demo 由项目的规则写答复。兼容 API 和本地模型通过 HTTP 接收问题、上下文和返回格式。模型服务用请求中的 `model` 选择要运行的模型。 [答复节点里的调用](../../backend/app/graph/career.py#L158-L163) · [真实提供器入口](../../backend/app/llm/provider.py#L163-L189)

**OpenAI 兼容接口**是一套请求与响应约定。`OpenAICompatibleProvider.generate_json` 把系统规则和本轮资料放入 `messages`，用 `response_format={"type":"json_object"}` 要求返回 JSON 对象。选用的服务需要支持这两项约定。下面的 `payload` 包含模型 ID 和消息，`headers` 可以携带 API Key。`await` 等模型服务返回后，`response.json()` 读外层响应，`content` 取第一条生成结果。生成结果在外层 JSON 里是字符串，所以后续还得解析一次。 [HTTP 发送与解析](../../backend/app/llm/provider.py#L66-L119)

```python
response = await client.post(
    f"{self.base_url}/chat/completions", headers=headers, json=payload
)
response.raise_for_status()
body = response.json()
content = body["choices"][0]["message"]["content"].strip()
```

### 先把三种地址记清

| 地址 | 谁访问 | 在哪里配置 |
| --- | --- | --- |
| `http://127.0.0.1:8030/docs` | 你的浏览器访问练习 API，选择接口并发请求 | 练习启动器的 `serve` |
| `http://localhost:8000/api/v1` | 工作台调用第 01 篇的 CareerLens 业务 API | 原仓库的 `frontend/lib/api.ts` 用 `NEXT_PUBLIC_API_URL` |
| 例如 `http://127.0.0.1:11434/v1` | CareerLens 后端访问模型进程 | `AI_BASE_URL` |

真正调用模型的路径由代码拼出来。例如配置 `AI_BASE_URL=http://127.0.0.1:11434/v1`，最后发往 `http://127.0.0.1:11434/v1/chat/completions`。在配置里写到 `/v1` 这一段即可。不同供应商若公布了其他基础地址，就按它公布的地址填写。 [地址拼接代码](../../backend/app/llm/provider.py#L104-L119) · [前端 API 入口](../../frontend/lib/api.ts#L3)

2. 展开 `POST /api/v1/profiles/{user_id}/rebuild`，点 **Try it out**。在路径的 `user_id` 输入格填 `agent-model-study`，执行后可以在响应中找到 Python。
3. 在 `POST /api/v1/chat` 发送第二段请求体。记下 `model.provider`、`model.model` 和 `evidence[0].evidence_id`。本次应看到 `provider="demo"`、`model="deterministic"`。Demo 的默认诊断里会有 `fallback: true`。

导入的请求体如下。

```json
{
  "user_id": "agent-model-study",
  "source_type": "self_statement",
  "source_name": "model-config-sample",
  "content": "我用 Python 和 FastAPI 做过课程接口，用 Docker 在本机运行。"
}
```

以后切换模型时保留同一个 SQLite 文件和用户，重新发同一句话。每次省略会话编号，从相同的输入开始。

```json
{
  "user_id": "agent-model-study",
  "message": "为什么认为我会 Python？",
  "mode": "rag"
}
```

用这个问句可以进入普通答复节点。问已有分析的岗位缺口、提出更改画像时，可能进入规则分支，`provider` 分别会显示 `job_analysis` 或 `workflow`。如果已经打开过 `answer` 关卡并看到 `TODO answer`，请先按下一课的提示补好答复函数，再来执行本实验。

## 先认清你要编辑的文件

在练习服务的终端按 Ctrl+C。在编辑器里新建 **`.cache/agent-practice/backend/.env.model`**。这是从项目根算的相对路径，若用过 `--workspace`，就改为该路径下的 `backend/.env.model`。用编辑器直接保存为 `.env.model` 可避免 Windows 自动加上 `.txt`。选择下面一条路线，把相应内容写进文件。密钥保存在本机的配置文件里，该文件在 Git 的忽略清单中。

给练习启动器加 `--use-model-config`，它会读取 `.env.model` 的模型设置，再把值交给后端。它自己安排 SQLite 和本地检索。普通的 `serve`、`worker` 和测试关卡直接使用 Demo，方便随时做对照。 [模型设置](../../backend/app/core/config.py#L32-L47) · [练习启动器](lab/practice.py)

### 路线一 · 使用兼容 API

在你使用的提供商控制台找到 **API 基础地址、API Key、模型 ID**。下面是一组兼容 API 的示例写法，三项真实值按服务文档填写，输入时去掉尖括号。

```dotenv
AI_PROVIDER=openai_compatible
AI_BASE_URL=https://<提供商域名和文档指定的基础路径>
AI_API_KEY=<控制台生成的 API Key>
AI_MODEL=<服务提供的模型 ID>
```

使用 DeepSeek 时可以改用下面的写法。把尖括号里的值替换为控制台和当前模型列表里的值。 [DeepSeek JSON 模式](https://api-docs.deepseek.com/guides/json_mode)

```dotenv
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_API_KEY=<控制台生成的 API Key>
AI_MODEL=<服务文档或模型列表里的模型 ID>
```

有密钥时，提供器会把它放在 `Authorization: Bearer …` 请求头里。调用云端模型时，本轮的上下文会发给该服务，可能按账号计费。用刚才的合成资料就能测试。

### 路线二 · 在电脑上运行模型

本例用 Ollama 提供本机的兼容接口。先按你的系统安装，在终端运行 `ollama --version` 确认命令可用。打开 Ollama 应用后，先用浏览器访问 [本机模型清单](http://127.0.0.1:11434/v1/models)。看到 JSON 就说明服务已启动，`data` 可以暂时为空。如果还连不上，在单独终端运行 `ollama serve`，保持它运行，再查一次地址。 [Ollama 安装](https://ollama.com/download) · [兼容接口文档](https://docs.ollama.com/api/openai-compatibility)

接着在另一个终端下载 `qwen2.5:3b`，或用清单里已有的模型。模型文件需要磁盘和内存，下载和首次回答可能需要等待。 [示例模型标签](https://ollama.com/library/qwen2.5:3b)

```bash
ollama pull qwen2.5:3b
ollama list
```

刷新模型清单，确认 `data` 中出现下载的模型 ID，再进入配置。

将下面的值写入练习副本的 `backend/.env.model`。`AI_MODEL` 以模型清单里的 ID 为准。

```dotenv
AI_PROVIDER=local
AI_BASE_URL=http://127.0.0.1:11434/v1
AI_API_KEY=
AI_MODEL=qwen2.5:3b
AI_TIMEOUT_SECONDS=120
```

这里 Qwen 是**生成**答复的模型，通过 `local` 选择提供器。仓库的 `RETRIEVAL_PROVIDER=qwen` 是另一层，负责检索中的 Embedding 或重排，配置生成模型时无需改它。 [实际提供器分支](../../backend/app/llm/provider.py#L163-L179)

## 启动并核对模型诊断

```bash
python tutorials/01-agent-design/lab/practice.py serve --use-model-config
```

回到 8030 的 Swagger，发送前面已经验证过的问句。用响应核对结果。打开 `evidence` 仍能对照答复引用的原文。

| `model` 的结果 | 下一步 |
| --- | --- |
| `provider` 是你选的值，`model` 是你填的模型 ID，`fallback=false` | 已经走到提供器并生成了能通过代码检查的答复。再核对引用支持力度 |
| `provider=demo` | 核对启动命令的开关、`.env.model` 所在目录和 `AI_PROVIDER`。DeepSeek 路径需要填入密钥 |
| `provider` 已切换，`fallback=true`、`reason=HTTPStatusError` | 上游返回了 HTTP 错误。对照供应商的请求记录或本地模型终端，检查基础地址、模型 ID、Key 和 JSON 模式支持 |
| `reason` 值形如 `ConnectError` 或 `ReadTimeout` | 先看模型服务进程和端口，再比较请求用时与 `AI_TIMEOUT_SECONDS` |
| `reason` 值形如 `JSONDecodeError` 或 `ValueError` | 查看 JSON 格式是否符合约定。已有候选时，检查答复是否引用了这些候选里的可用 ID |

可以做一次复现练习。先写下成功时的 `model` 字段，再把 **本地** `AI_MODEL` 改成模型清单里找不到的 ID，重启并发同样的问题。CareerLens 对话仍可能返回 200，因为答复节点会交回模板，请同时记录 `fallback` 和 `reason`。改回原值后再测一次。选云端的读者可以直接读后面源码课的假提供器测试，复现输出格式和引用错误。

### 把配置接回第 01 篇的工作台

已通过 Compose 启动原项目、想在工作台试同一个生成模型时，编辑**原项目根**的 `.env`。写入对应的 `AI_*` 项，从项目根运行下列命令，使 API 和 Worker 取得新的环境变量。此时仍用工作台和原项目的 8000 端口。 [Compose API 与 Worker 的配置](../../docker-compose.yml#L1-L20)

```bash
docker compose up -d --force-recreate api worker
```

如果模型在宿主机、CareerLens API 在容器里，容器里的 `127.0.0.1` 指向容器自己。Docker Desktop 可用 `http://host.docker.internal:11434/v1` 指向宿主机，同时需要宿主模型服务能接受这条连接。初次使用本地模型时，先跑通直接连本机的 8030 练习，有了成功响应再切到容器。 [项目配置文档中的「对话模型」一节](../../docs/api-and-configuration.md)

如果想让练习 Worker 也调用模型，从项目根运行 `python tutorials/01-agent-design/lab/practice.py worker --use-model-config`，它会读取同一个练习文件。

### 选学 按角色配置模型

源码取答复提供器时用 `get_llm_provider("answer")`。如果设置了 `MODEL_ROLE_BINDINGS=answer=模型A,analysis=模型B`，相应角色会选择对应的模型 ID，没有绑定的角色继续用 `AI_MODEL`。不同角色在这里仍共享同一条 `AI_BASE_URL` 和 `AI_API_KEY`。先跑通默认模型 ID，再考虑按角色调整。 [按角色解析和回落](../../backend/app/core/config.py#L85-L100)
