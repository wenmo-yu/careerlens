# 模型配置 · 从 Demo 切换到兼容 API 或本地模型

上一课让程序按名字调用一个工具。取回原文后，轮到答复节点组织回答。先用一条合成资料跑出 Demo 对照，再按自己的环境选做兼容 API 或本地模型。跑过 Demo 就可以进入下一课，后面的关卡测试也都能用 Demo。

## 本课先懂的技术

**模型提供器（provider）**是后端里负责调用模型的一层。在 `backend/app/graph/career.py` 搜 `get_llm_provider("answer")` 看调用，在 `backend/app/llm/provider.py` 搜 `def get_llm_provider` 看定义。这个函数为答复角色选择实现。Demo 由项目的规则写答复。兼容 API 和本地模型通过 HTTP 接收问题、上下文和返回格式。模型服务用请求中的 `model` 选择要运行的模型。 [答复节点里的调用](../../backend/app/graph/career.py#L158-L163) · [真实提供器入口](../../backend/app/llm/provider.py#L163-L189)

**OpenAI 兼容接口**是一套请求与响应约定。`OpenAICompatibleProvider.generate_json` 把系统规则和本轮资料放入 `messages`，用 `response_format={"type":"json_object"}` 要求返回 JSON 对象。选用的服务需要支持这两项约定。下面的 `payload` 包含模型 ID 和消息，`headers` 可以携带 API Key。`await` 等模型服务返回后，`response.json()` 读外层响应，`content` 取第一条生成结果。生成结果在外层 JSON 里是字符串，所以后续还得解析一次。 [HTTP 发送与解析](../../backend/app/llm/provider.py#L66-L119)

```python
response = await client.post(
    f"{self.base_url}/chat/completions", headers=headers, json=payload
)
response.raise_for_status()
body = response.json()
content = body["choices"][0]["message"]["content"].strip()
```

### 先把三种地址记清

| 地址 | 谁访问 | 在哪里配置 |
| --- | --- | --- |
| `http://127.0.0.1:8030/docs` | 你的浏览器访问练习 API，选择接口并发请求 | 练习启动器的 `serve` |
| `http://localhost:8000/api/v1` | 工作台调用第 01 篇的 CareerLens 业务 API | 原仓库的 `frontend/lib/api.ts` 用 `NEXT_PUBLIC_API_URL` |
| 例如 `http://127.0.0.1:11434/v1` | CareerLens 后端访问模型进程 | `AI_BASE_URL` |

真正调用模型的路径由代码拼出来。例如配置 `AI_BASE_URL=http://127.0.0.1:11434/v1`，最后发往 `http://127.0.0.1:11434/v1/chat/completions`。在配置里写到 `/v1` 这一段即可。不同供应商若公布了其他基础地址，就按它公布的地址填写。 [地址拼接代码](../../backend/app/llm/provider.py#L104-L119) · [前端 API 入口](../../frontend/lib/api.ts#L3)

### 路线一 · 使用兼容 API

在你使用的提供商控制台找到 **API 基础地址、API Key、模型 ID**。下面是一组兼容 API 的示例写法，三项真实值按服务文档填写，输入时去掉尖括号。

```dotenv
AI_PROVIDER=openai_compatible
AI_BASE_URL=https://<提供商域名和文档指定的基础路径>
AI_API_KEY=<控制台生成的 API Key>
AI_MODEL=<服务提供的模型 ID>
```

使用 DeepSeek 时可以改用下面的写法。把尖括号里的值替换为控制台和当前模型列表里的值。 [DeepSeek JSON 模式](https://api-docs.deepseek.com/guides/json_mode)

```dotenv
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_API_KEY=<控制台生成的 API Key>
AI_MODEL=<服务文档或模型列表里的模型 ID>
```

有密钥时，提供器会把它放在 `Authorization: Bearer …` 请求头里。调用云端模型时，本轮的上下文会发给该服务，可能按账号计费。用刚才的合成资料就能测试。

### 路线二 · 在电脑上运行模型

**Ollama 是装在你电脑上的模型运行程序。** 它负责下载模型文件、在接到问题时加载模型，并通过本机 HTTP 接口把生成结果交给其他应用。**Qwen2.5 是模型**。这次用 `qwen2.5:3b` 这个完整名称告诉 Ollama 要加载哪一版。浏览器把问题交给 8030 的 CareerLens，CareerLens 查到原文后，再把问题和证据发给 11434 的 Ollama。直接跳到本节的读者，可以先准备对照用的账号和资料。 [本页的 Demo 实验](#先跑一条不花费用的对照) · [Ollama 本机接口](https://docs.ollama.com/api/openai-compatibility)

#### 第一步 安装 Ollama

**Windows**

1. 在官方下载页选择手动下载，拿到 `OllamaSetup.exe`。 [Windows 下载](https://ollama.com/download/windows)
2. 双击下载的文件，按安装窗口完成安装。安装后 Ollama 通常会在后台运行，也可以从开始菜单打开 **Ollama**。
3. 重新打开一个 PowerShell 窗口，执行 `ollama --version`。看到版本号表示终端能找到 Ollama 命令。 [Windows 安装说明](https://docs.ollama.com/windows)

**macOS**

1. 下载 Ollama 的 `.dmg` 安装包，双击打开，将 **Ollama** 拖入「应用程序」。 [macOS 下载](https://ollama.com/download/mac)
2. 从「应用程序」打开 Ollama。首次启动如果提示添加命令行工具，按提示允许添加。
3. 打开新的终端窗口，运行 `ollama --version`。 [macOS 安装说明](https://docs.ollama.com/macos)

**Linux**

在终端运行官方安装命令，再查看版本。使用 systemd 的系统上，安装完成后可用 `systemctl status ollama` 查看服务状态。 [Linux 安装说明](https://docs.ollama.com/linux)

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama --version
```

#### 第二步 确认 Ollama 服务已启动

打开 [本机模型清单](http://127.0.0.1:11434/v1/models)。能看到 JSON 就说明 Ollama 正在响应。刚装好时 `data` 可能是空数组，可以继续下载模型。这一步只验证服务和模型清单。随后会发一个问题，确认它也能生成答复。

浏览器提示连接失败时，先确认 Ollama 应用已经打开。若你只安装了命令行版，或系统里没有运行中的 Ollama 服务，在单独的终端执行下面这条命令，把窗口留着，然后刷新模型清单。遇到 `address already in use` 时先刷新清单。若可以正常读取 JSON，就沿用已在监听的 Ollama。 [启动服务和模型接口](https://docs.ollama.com/cli#start-ollama) · [模型清单接口](https://docs.ollama.com/api/openai-compatibility#v1-models)

```bash
ollama serve
```

#### 第三步 下载一版模型，先在终端试一句

在另一个终端运行下面两行。第一行把模型下载到电脑，第二行列出已下载的模型。`3b` 表示这一版大约有 30 亿参数，Ollama 模型库中该版本的下载大小约为 **1.9 GB**。首次下载需要网络，生成答复时还需要运行内存。 [模型版本与大小](https://ollama.com/library/qwen2.5:3b) · [CLI 命令说明](https://docs.ollama.com/cli)

```bash
ollama pull qwen2.5:3b
ollama list
```

看到下载完成后，核对 `ollama list` 的 `NAME` 列有 `qwen2.5:3b`。刷新 [本机模型清单](http://127.0.0.1:11434/v1/models)，也能在 `data` 下找到 `"id": "qwen2.5:3b"`。跑不动 3B 版本时，可以下载较小的 `qwen2.5:1.5b`，后续的 `run` 和 `AI_MODEL` 都换成实际下载的完整名字。 [Qwen2.5 1.5B 版本](https://ollama.com/library/qwen2.5:1.5b)

接着直接运行模型。命令会进入对话界面，第一次加载可能需要等一会儿。

```bash
ollama run qwen2.5:3b
```

看到 `>>>` 后，输入「请用一句中文说明 Python 可以用来做什么。」模型应在终端生成一条回复，例如「Python 可以用来处理数据、编写脚本和开发应用。」看到回复后，输入 `/bye` 退出这次命令行对话，保持 Ollama 服务运行。现在已经单独验证了本机模型能回答，可以接入 CareerLens。

#### 第四步 把刚才验证过的地址和模型名填进 CareerLens

回到编辑器，打开 **`.cache/agent-practice/backend/.env.model`**。若 01-A 使用了自选目录，就打开那个练习副本里的 `backend/.env.model`。例如练习目录为 `.cache/agent-practice-2` 时，文件就在 `.cache/agent-practice-2/backend/.env.model`。保存下面的内容。如果第三步选了别的模型，只替换 `AI_MODEL` 的值。

```dotenv
AI_PROVIDER=local
AI_BASE_URL=http://127.0.0.1:11434/v1
AI_API_KEY=
AI_MODEL=qwen2.5:3b
AI_TIMEOUT_SECONDS=120
```

`AI_PROVIDER=local` 让 CareerLens 走兼容 HTTP 提供器。`AI_BASE_URL` 写到 `/v1`，程序随后拼上 `/chat/completions`。`AI_API_KEY` 留空，本机 Ollama 可以直接接收这次 HTTP 请求。`AI_TIMEOUT_SECONDS=120` 给模型加载和生成预留等待时间。切换后仍沿用当前练习副本里的证据和本地检索。 [Ollama 的兼容接口](https://docs.ollama.com/api/openai-compatibility) · [CareerLens 提供器选择](../../backend/app/llm/provider.py#L163-L179)

## 启动并核对模型诊断

在项目根打开之前跑 Demo 的终端。若 Demo API 还在运行，按 Ctrl+C 停止它，再用下面的命令读取新配置。选择 Ollama 路线时保留第二步打开的 Ollama 服务。

```bash
python tutorials/01-agent-design/lab/practice.py serve --use-model-config
```

用了自选练习目录时，把同一个 `--workspace` 传回去。例如 `python tutorials/01-agent-design/lab/practice.py --workspace .cache/agent-practice-2 serve --use-model-config`。

打开 [8030 的 Swagger](http://127.0.0.1:8030/docs)，用前面的账号 `agent-model-study` 在 `POST /api/v1/chat` 重发「为什么认为我会 Python？」，`mode` 仍为 `rag`。同一份 SQLite 已保存练习材料，可直接使用之前的请求体。Ollama 接入成功且回答通过校验时，响应里的 `model` 应像这样。

```text
"model": {
  "provider": "local",
  "model": "qwen2.5:3b",
  "fallback": false
}
```

再看响应的 `answer` 和 `evidence`。答复里的 `[Evidence: …]` 可以和 `evidence` 里的真实 ID 对照，合成原文只描述做过课程接口、用 Docker 在本机运行。看到 HTTP 200 后继续检查 `fallback`，因为备用答复也能通过同一个聊天接口返回。

| `model` 的结果 | 下一步 |
| --- | --- |
| `provider` 是你选的值，`model` 是你填的模型 ID，`fallback=false` | 已经走到提供器并生成了能通过代码检查的答复。再核对引用支持力度 |
| `provider=demo` | 核对启动命令的开关、`.env.model` 所在目录和 `AI_PROVIDER`。DeepSeek 路径需要填入密钥 |
| `provider` 已切换，`fallback=true`、`reason=HTTPStatusError` | 上游返回了 HTTP 错误。对照供应商的请求记录或本地模型终端，检查基础地址、模型 ID、Key 和 JSON 模式支持 |
| `reason` 值形如 `ConnectError` 或 `ReadTimeout` | 先看模型服务进程和端口，再比较请求用时与 `AI_TIMEOUT_SECONDS` |
| `reason` 值形如 `JSONDecodeError` 或 `ValueError` | 查看 JSON 格式是否符合约定。已有候选时，检查答复是否引用了这些候选里的可用 ID |

本机 Ollama 排错时可以按层检查。`/v1/models` 读不到就回第二步检查服务。清单里已有模型、`ollama run` 仍无法回复，就先看模型是否成功加载。命令行可以回答而 Swagger 回退时，再核对 `AI_BASE_URL` 的 `/v1`、完整模型名，以及诊断里的 `reason`。首次加载超过 120 秒时，可先用 `ollama run` 让模型成功回答过一次，再重试同一请求，或调高 `AI_TIMEOUT_SECONDS` 后重启练习 API。

可以做一次复现练习。先写下成功时的 `model` 字段，再把 **本地** `AI_MODEL` 改成模型清单里找不到的 ID，重启并发同样的问题。CareerLens 对话仍可能返回 200，因为答复节点会交回模板，请同时记录 `fallback` 和 `reason`。改回原值后再测一次。选云端的读者可以直接读后面源码课的假提供器测试，复现输出格式和引用错误。

### 把配置接回第 01 篇的工作台

已通过 Compose 启动原项目时，可以把同一模型接到工作台。用云端兼容 API 的读者把对应的 `AI_*` 项写入**原项目根**的 `.env`，然后执行下方的重建命令。

```bash
docker compose exec api python -c "from urllib.request import urlopen; print(urlopen('http://host.docker.internal:11434/v1/models', timeout=5).read().decode())"
```

看到正确的模型名后，把第四步的 `AI_*` 设置填到**原项目根**的 `.env`，其中 `AI_BASE_URL` 写成 `http://host.docker.internal:11434/v1`。探测失败时，继续用前面的 8030 练习，并按 Ollama 的说明核对服务监听地址。 [Ollama 服务配置](https://docs.ollama.com/faq#how-do-i-configure-ollama-server) · [项目配置文档中的「对话模型」一节](../../docs/api-and-configuration.md)
