# 09 画像、自陈测评与 GitHub 导入

林澈补了两条课程项目的记录，又做了一次工作偏好自测。哪种输入能改变岗位分数？这一章用同一个测试账号做两次岗位分析，核对前后数据。动手部分可以使用第 01 篇的 Swagger 或 8030 的练习副本。GitHub 导入和添加量表是选做。阅读约 15 分钟，验证约 20 分钟。 [练习环境](setup/动手准备.md#核对环境与编号)

## 9.1 三个抽屉，不要混

| 抽屉 | 里面放什么 | 能不能当事实 | 会不会改匹配分 |
| --- | --- | --- | --- |
| 证据 Evidence | 你上传或粘贴的原文，带来源、时间、定位 | 是原文，不是结论 | 会，抽取出的技能参与匹配 |
| 事实画像 ProfileItem | 从证据抽取并确认的技能、经历 | 是，但要看证据覆盖 | 会 |
| 自陈测评 AssessmentResult | 你选择的答案、分数、偏好组合 | **不是** | **不会** |

「我觉得自己擅长沟通」可以放在自陈结果里供本人反思。量表页会提供兴趣方向提示。岗位匹配和按技能覆盖度生成的岗位推荐仍读取可追溯的技能画像。 [岗位推荐代码](../backend/app/services/recommendation.py)

## 9.2 先看导入结果卡

在「导入」里上传一份 PDF 或粘贴一段文字，结果卡会告诉你：读到几条、复用几条、有多少页待 OCR、失败原因、证据在哪里。任务成功不等于读出文字——扫描页会明确标 `ocr_pending`，不会伪造内容。

然后打开画像概览 `GET /api/v1/profiles/{user_id}/overview`，重点看三个数：

- `coverage.supported`：至少两条有效证据，且置信度达到 0.7；
- `coverage.weak`：有证据，但仅有一条有效证据，或置信度低于 0.7；
- `coverage.missing`：当前仍保留的画像条目找不到任何有效证据。

三类计数针对当前画像条目。用下面 9.4 的两条材料练习时，删掉其中一条会从 `supported` 变成 `weak`。如果最后一条可引用证据也被删掉，对应的条目可能随之移除，此时可观察 `profile_item_count`。把删除实验放在 9.4 结束后，只操作新建的合成账号。 [覆盖度实现](../backend/app/services/profile_overview.py) · [删除和引用更新](../backend/app/services/privacy.py)

## 9.3 三份量表从哪来

题库在 `backend/app/assessment/data/`，全部是项目自写；每份 JSON 的 `license.not_used` 写清了没有采用哪些来源：

| 量表 | 题量 | 输出 | 没采用的来源 |
| --- | --- | --- | --- |
| `work_style_4d` | 32 | 四组偏好百分比、字母组合、接近中点提示 | MBTI®、OEJTS（CC BY-NC-SA） |
| `riasec_interest` | 48 | 六维兴趣、前三代码、一致性、分化度 | O*NET Interest Profiler（CC BY-ND，禁止改编/翻译） |
| `big_five_20` | 20 | 五维位置与分档、工作风格提示 | NEO-PI-3、BFI-2（商业/学术版权） |

计分规则很短：

```text
位置 = (该维度已答题均值 - 量表最小值) / (最大值 - 最小值) × 100
```

- 至少答 80% 才计分，每个维度至少答一半；未答项不插补。
- 双极量表两个方向均值差小于 10% 标为「接近中点」，不硬凑类型。
- 大五反向题先翻转（`min + max - 原值`）。
- RIASEC 取最高三项组成代码，看相邻字母在 `R—I—A—S—E—C—R` 环上的最短距离。R–I 与 C–R 都是一格，`CRI` 的两对都是一格，因此一致性为「高」。 [计分实现](../backend/app/assessment/scoring.py)

完整许可比对与公式见 [测评题库与许可](../docs/assessments.md)。

## 9.4 动手：提交一次完整的四维偏好

在 [8000 Swagger](http://localhost:8000/docs) 准备一个新账号 `learner-assessment`。在 `POST /api/v1/evidence/text` 按下面的内容提交两次，第二次把项目编号 1 改成 2。之后调用 `POST /api/v1/profiles/{user_id}/rebuild`。如果你改了账号，本节的请求和路径都使用同一个值。

```json
{
  "user_id": "learner-assessment",
  "content": "用 Python 做过课程项目 1。"
}
```

先从 `GET /api/v1/profiles/{user_id}/overview` 抄下 `coverage`、`profile_item_count` 与 `assessments`。向 `POST /api/v1/jobs/analyze` 发送以下请求，记下分数 `50.0`：

```json
{
  "user_id": "learner-assessment",
  "title": "后端实习",
  "jd_text": "岗位必需熟悉 Python 和 Docker。",
  "weekly_hours": 6
}
```

1. 打开 `GET /api/v1/assessments/instruments/work_style_4d`，检查 `item_count=32`，找到第一题的 ID。公开题目里保留填写所需的信息，计分键留在服务端。
2. 到 `POST /api/v1/assessments/instruments/work_style_4d/submit`。先只给两题，预测是否保存：

```json
{"user_id":"learner-assessment","consent":true,"answers":{"ws-ei-01":5,"ws-ei-05":4}}
```

预期 422，提示「至少需要回答 26/32 题，当前 2 题」。重新查询画像概览，`assessments` 仍为空。

3. 打开[可直接提交的 32 题合成答案](../examples/tutorials/fixtures/work-style-neutral.json)，复制整份 JSON 到相同提交接口。每题都是 3，表示这组测试数据对两个方向给了相同分。预期返回 200，`result.code="????"`，`clarity=0.0`，四个维度都接近中点。
4. 再读一次画像概览，再用相同 JSON 调一次 `POST /api/v1/jobs/analyze`。你的记录应能填成下面这张表：

| 核对项 | 自测前 | 自测成功后 |
| --- | --- | --- |
| `profile_item_count` | 1 | 1 |
| `coverage.supported / weak / missing` | 1 / 0 / 0 | 1 / 0 / 0 |
| 岗位分 | 50.0 | 50.0 |
| `assessments` | 空 | 一份最新四维偏好结果 |

试着只改变作答内容，再看 `assessments` 的结果。概览对每种量表展示最近一次结果，复测会更新这一种量表的概览项。 [测评路由](../backend/app/api/routes/assessment.py) · [实际回归测试](../backend/tests/test_assessment_instruments.py)

## 9.5 选做 · GitHub 导入

平台 OAuth 需要注册应用、密钥和回调，本项目没有做。GitHub 走另一条路：你自己建一个最小权限令牌，系统读一次，令牌不保存。

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens**。
2. Repository access 只选要导入的仓库。
3. Permissions：**Contents = Read-only**、**Metadata = Read-only**。
4. 过期时间选 7 天；生成后复制。
5. 工作台「GitHub 仓库」表单粘贴，填 `owner/name`（留空则取最近推送的 10 个）。

服务端只读仓库简介、语言、Star、Fork、可见性和 README（截断 6000 字符）。令牌只在这一次请求的内存里。纯本地跟做可先读[合成仓库导入测试](../backend/tests/test_github_connector.py)，核对哪段 README 被保存为证据。细节与排错见 [GitHub 仓库导入](../docs/github-token-import.md)。

## 9.6 选做 · 验证一份自己的量表

打开[两维六题的完整样例](../examples/tutorials/fixtures/my_scale.json)。它包括计划与复查两个维度。每维三题、各含一题反向题，`instrument_id` 与文件名一致。量表由本课原创题目构成，题意只用于练习代码。

在项目根使用[后端练习的同一个 Python](setup/动手准备.md#给源码练习准备一套-python)，直接用项目加载器对示例做校验：

```bash
python -c "import json; from pathlib import Path; from app.assessment.loader import _validate; p = Path('examples/tutorials/fixtures/my_scale.json'); scale = _validate(json.loads(p.read_text(encoding='utf-8')), p.name); print(scale['instrument_id'], len(scale['items']))"
```

预期输出 `my_scale 6`。接着复制到 `.cache/my_scale.json`。只删掉 `ms-p-03` 的 `reverse: true` 字段，把命令中 `Path(...)` 的路径换成这份副本，再跑一次，预期报「dimension P needs both keyed and reverse items」。恢复字段后再跑一遍。加载器同时核对维度、题量与反向题。 [量表加载代码](../backend/app/assessment/loader.py)

## 9.7 验收清单

- [ ] 能说出 Evidence、ProfileItem、AssessmentResult 三者的边界。
- [ ] 能用两条合成原文解释为何画像标为 supported，并在删去其中一条后看到 weak。
- [ ] 提交不足 80% 的答案会得到 422，而不是被悄悄补齐。
- [ ] 提交一次测评后，`coverage` 与匹配分不变，`assessments` 多一条。
- [ ] 能解释为何两次岗位分相同。若选做 GitHub 导入，能在结果里找到授权仓库的 README 证据。
- [ ] 能指出 `license.not_used` 里至少两个未采用来源及原因。

继续 [08-3 贡献与结课](08-advanced/08-3-贡献与结课.md)，把两次岗位分和本次合成输入写成交付记录。想学怎样编排门禁，再去做 [08-2 评测](08-advanced/08-2-评测.md)。
