# 09 画像、自陈测评与 GitHub 导入

这一章把「证据 → 画像 → 自陈」三件事分开，再动手加一份量表、接一次 GitHub。学完你应该能回答：为什么系统愿意给你看一个分数，却不愿意拿它去改岗位匹配。

## 9.1 三个抽屉，不要混

| 抽屉 | 里面放什么 | 能不能当事实 | 会不会改匹配分 |
| --- | --- | --- | --- |
| 证据 Evidence | 你上传或粘贴的原文，带来源、时间、定位 | 是原文，不是结论 | 会，抽取出的技能参与匹配 |
| 事实画像 ProfileItem | 从证据抽取并确认的技能、经历 | 是，但要看证据覆盖 | 会 |
| 自陈测评 AssessmentResult | 你选择的答案、分数、偏好组合 | **不是** | **不会** |

系统宁可让画像单薄，也不把「我觉得自己擅长沟通」直接写成技能。测评结果只是让你多一个反思角度，以及给推荐提供软排序线索。

## 9.2 先看导入结果卡

在「导入」里上传一份 PDF 或粘贴一段文字，结果卡会告诉你：读到几条、复用几条、有多少页待 OCR、失败原因、证据在哪里。任务成功不等于读出文字——扫描页会明确标 `ocr_pending`，不会伪造内容。

然后打开画像概览 `GET /api/v1/profiles/{user_id}/overview`，重点看三个数：

- `coverage.supported`：有有效证据、且证据不止一条或置信度够；
- `coverage.weak`：只有一条证据，或置信度低于 0.7；
- `coverage.missing`：画像条目找不到任何仍然存在的证据。

这三个数只描述你已有的数据，不产生新结论。删掉一条证据，`supported` 会掉到 `weak` 或 `missing`——可以自己试一次，这是理解「可回查」最快的方法。

## 9.3 三份量表从哪来

题库在 `backend/app/assessment/data/`，全部是项目自写；每份 JSON 的 `license.not_used` 写清了没有采用哪些来源：

| 量表 | 题量 | 输出 | 没采用的来源 |
| --- | --- | --- | --- |
| `work_style_4d` | 32 | 四组偏好百分比、字母组合、接近中点提示 | MBTI®、OEJTS（CC BY-NC-SA） |
| `riasec_interest` | 48 | 六维兴趣、前三代码、一致性、分化度 | O*NET Interest Profiler（CC BY-ND，禁止改编/翻译） |
| `big_five_20` | 20 | 五维位置与分档、工作风格提示 | NEO-PI-3、BFI-2（商业/学术版权） |

计分规则很短：

```text
位置 = (该维度已答题均值 - 量表最小值) / (最大值 - 最小值) × 100
```

- 至少答 80% 才计分，每个维度至少答一半；未答项不插补。
- 双极量表两个方向均值差小于 10% 标为「接近中点」，不硬凑类型。
- 大五反向题先翻转（`min + max - 原值`）。
- RIASEC 取最高三项组成代码；相邻字母越连续，一致性越高。

完整许可比对与公式见 [测评题库与许可](../docs/assessments.md)。

## 9.4 动手：提交一次四维偏好

```bash
# 1. 看有哪些量表
curl -s http://localhost:8000/api/v1/assessments/instruments | python -m json.tool

# 2. 取题目（响应里没有计分键和反向标记）
curl -s http://localhost:8000/api/v1/assessments/instruments/work_style_4d \
  | python -c "import json,sys; d=json.load(sys.stdin); print(d['item_count']); print(d['items'][0])"

# 3. 提交（示例只给两题，真实提交需 ≥ 80%）
curl -s -X POST http://localhost:8000/api/v1/assessments/instruments/work_style_4d/submit \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"u1","consent":true,"answers":{"ws-ei-01":5,"ws-ei-05":4}}'
```

第三步会得到 422：系统会告诉你还差多少题。这比默默用中性值补齐更诚实。

答满后再提交，响应里的 `result.code` 是四维组合，`result.clarity` 是平均强度，`result.balanced_dimensions` 列出接近中点的维度。接着看画像概览，`assessments` 数组会多一条最近结果，但 `coverage` 和 `profile_item_count` 一个都没变——这就是边界。

## 9.5 GitHub：自己给一个只读令牌

平台 OAuth 需要注册应用、密钥和回调，本项目没有做。GitHub 走另一条路：你自己建一个最小权限令牌，系统读一次，令牌不保存。

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens**。
2. Repository access 只选要导入的仓库。
3. Permissions：**Contents = Read-only**、**Metadata = Read-only**。
4. 过期时间选 7 天；生成后复制。
5. 工作台「GitHub 仓库」表单粘贴，填 `owner/name`（留空则取最近推送的 10 个）。

服务端只读仓库简介、语言、Star、Fork、可见性和 README（截断 6000 字符），不读 issues、PR、commit。令牌只在这一次请求的内存里，不写库、不写日志。细节与排错见 [GitHub 仓库导入](../docs/github-token-import.md)。

## 9.6 加一份自己的量表

复制一份现有 JSON 改名为 `my_scale.json`，`instrument_id` 必须与文件名一致：

```json
{
  "instrument_id": "my_scale",
  "version": "2026.11",
  "title": "示例量表",
  "subtitle": "12 题",
  "construct": "说明测什么、不测什么",
  "estimated_minutes": 3,
  "response_scale": {"min": 1, "max": 5, "labels": ["很不符合","不太符合","一般","比较符合","很符合"], "prompt": "是否符合你？"},
  "license": {"items": "project-authored", "license": "MIT", "attribution": "题目自写", "not_used": ["某商业量表：未复制"]},
  "disclaimer": "未做信效度验证，不用于招聘或医疗。",
  "scoring": {"type": "trait"},
  "dimensions": [{"key": "X", "label": "维度", "description": "说明", "high": "高分提示", "low": "低分提示"}],
  "items": [{"id": "ms-x-01", "text": "题目文字", "dimension": "X"}]
}
```

跑 `pytest tests/test_assessment_instruments.py`。加载器会检查：ID 唯一、维度存在、每个维度至少 3 题、双极量表每极至少 3 题、特质量表同时有正向与反向题、许可与免责声明齐全。改坏一个字段会直接报错。

## 9.7 验收清单

- [ ] 能说出 Evidence、ProfileItem、AssessmentResult 三者的边界。
- [ ] 删掉一条证据后，画像覆盖度从 supported 变成 weak 或 missing。
- [ ] 提交不足 80% 的答案会得到 422，而不是被悄悄补齐。
- [ ] 提交一次测评后，`coverage` 与匹配分不变，`assessments` 多一条。
- [ ] 能用最小权限令牌导入一个仓库，并说清系统没有保存令牌。
- [ ] 能指出 `license.not_used` 里至少两个未采用来源及原因。
