## 附：一份已填写的样例成品（照着填，不要照抄结论）

下面用仓库的两份评测夹具完成样例。你可以复跑同样的命令，再记录自己对排序变化的解释。

**我的案例**：虚构学习者林澈，目标岗位为 AI Agent 开发。检索评测的参考版本为 [`05a9e41`](https://github.com/wenmo-yu/careerlens/commit/05a9e41faad59120f8bf9a8dfd86351201bf097e)，输入文件为 `eval/datasets/recall2-demo.json` 和 `eval/datasets/recall2-demo-bookmark.json`。运行环境为已安装后端依赖的 Python 和本地规则检索。

**一、我做的实验**

| 环节 | 内容 |
| --- | --- |
| 固定输入 | 最小数据集 `eval/datasets/recall2-demo.json`：一个查询固定为「LangGraph Agent 状态管理 Qdrant RAG 证据检索」，标 2 条相关证据 `ev-rel-a`/`ev-rel-b`，K=2 |
| 我改的一个变量 | `evidence` 里是否追加 `ev-bookmark`（正文含查询全文，但**不**加进相关证据列表） |
| 我的预测（改前写） | 收藏卡含查询全文会拿 exact_bonus 排第一，挤掉一条相关证据；Recall@2 从 2/2 降到 1/2 |
| 实际结果 + 为什么 | 无卡 `1.0`、Top2=`[ev-rel-a, ev-rel-b]`；有卡 `0.5`、Top2=`[ev-bookmark, ev-rel-a]`。命中 2→1、分母仍 2（`runner.py:66-70`、`hybrid.py:51`） |

**给复跑者的完整命令**。在仓库根激活[课程 Python 环境](setup/动手准备.md#给源码练习准备一套-python)，按顺序执行：

```bash
python examples/tutorials/lesson-06-eval/main.py
cd backend
python -m app.evaluation.cli --dataset ../eval/datasets/recall2-demo.json --baseline ../eval/baselines/recall2-demo.json
python -m app.evaluation.cli --dataset ../eval/datasets/recall2-demo-bookmark.json --baseline ../eval/baselines/recall2-demo.json
```

先从练习脚本核对两组 Top-2。第一条门禁命令预期输出 `passed` 并退出 0，第二条预期 `failed` 并退出 1。PowerShell 在每条门禁命令后读 `$LASTEXITCODE`，Bash 读 `echo $?`。负例的 `failures` 为 `[{"metric":"evidence_recall_at_k","actual":0.5,"minimum":0.75,"delta":-0.25}]`。这是同一个门槛下只切换数据集的对照。 [08-2 评测](08-advanced/08-2-评测.md)

**二、结论**：同一查询只因一条未标相关的收藏卡进入 Top-2，召回从满分掉到半分；收藏不是技能证据，**标注集合决定系统算不算命中**。

**三、引用**

| 结论 | 证据 | 原文出处 |
| --- | --- | --- |
| Recall@K 分母是相关数 | `backend/app/evaluation/runner.py:66-70` | `len(retrieved & relevant) / len(relevant)` |
| 收藏卡命中全文短语并进入前二 | `ev-bookmark`、`backend/app/retrieval/hybrid.py` | 查询整句出现在卡片正文里，`exact_bonus` 为 `0.25`。加入卡片也会改变词的文档频率 |

`ev-rel-a`→「LangGraph Agent 状态管理」；`ev-rel-b`→「Qdrant RAG 证据检索」；`ev-bookmark`→「收藏教程 LangGraph Agent 状态管理 Qdrant RAG 证据检索 补充说明」（均合成）。

**四、缺口**：「收藏教程」是否说明林澈掌握 LangGraph/RAG——**证据不足**。本实验只证明排序受正文影响，`supported_claim_rate` 只是别名+ID 代理校验，不做语义事实核查。

**五、下一步**：做 [08-1 的导入实验](08-advanced/08-1-真实模型.md)。先比较纯收藏与实际部署的 `claim_strength`，再重建画像核对技能依据。评测里的收藏卡可以进入候选列表，是否能支持技能需要回到原文。

**六、验证**

- 关键输出（原样贴）：

```text
无收藏卡  Recall@2=1.0  Top2=['ev-rel-a','ev-rel-b']
有收藏卡  Recall@2=0.5  Top2=['ev-bookmark','ev-rel-a']
```

- 未验证项：真实模型（Qdrant + 真实 provider）的召回、真实用户数据的准确率、`AUTH_MODE=required` 下 REST 权限路径。冻结 v3 的四项 1.0 不是生产准确率。
