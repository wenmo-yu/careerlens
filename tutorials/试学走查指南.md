# 样板课试学走查指南（给组织者）

这份指南用来回答一个问题：**第 04 篇样板课，一个没接触过项目的人能不能真的学下去？**

它把「请两位读者独立试学」拆成可直接执行的动作：你只要找两个人、各给一张任务卡、让他们边做边填一张表，就能得到可复盘的结论。**组织者不要在旁边提示**——读者卡住本身就是要观察的数据。

---

## 一、找两位读者（画像明确）

| 读者 | 画像 | 为什么需要 |
| --- | --- | --- |
| **读者 A · 零安装** | 从没写过代码、没装过 Docker/Python，平时只用浏览器 | 验证阶段 0 和 04 环节一/二/四能否纯浏览器 + 标准库之外完成；英文术语和命令行是不是门槛 |
| **读者 B · 懂基础** | 会写简单 Python、用过终端，但没看过本项目 | 验证环节二改代码、环节三接回真实源码的路径是否清楚；技术讲解是否够深又不绕 |

两人**都不要提前看本指南或答案**。给他们的唯一入口是 [开始页](从这里开始.md)。

## 二、给读者的任务卡（直接转发）

> ### 你的任务
>
> 从 [CareerLens 开始页](从这里开始.md) 出发，自己走到第 04 篇「为什么这条证据排第一，却不能支持这句结论？」，按课文做完能做的部分。
>
> 规则：
> 1. 遇到不懂的先记下来，不要问组织者，也不要跳读答案折叠块——先看自己能不能推出来。
> 2. 每做完一个环节，在下面的记录表写一行：**做了什么、卡在哪、花了多久**。
> 3. 遇到装软件、开通账号、付费的提示，先停下来记「到这里我停了」，不用真的做。
> 4. 目标不是「全做完」，而是让我们知道你**在哪里开始卡住**。
>
> 读完请交：① 填好的记录表；② 你对这三个问题的回答：「RRF 融合在奖励什么？」「排第一的材料为什么可能不能用？」「你最想跳过的是哪一段，为什么？」

## 四、组织者评分（只看结果，不看步数）

对每位读者，回答下面四问，每问记「通过 / 部分 / 受阻」并附一句原话：

| 检查点 | 通过标准 | 读者 A | 读者 B |
| --- | --- | --- | --- |
| 能进门 | 从开始页自己走到 04，不需要指路 |  |  |
| 能复算 | 手算融合分数答对「两榜都中 > 一榜榜首」 |  |  |
| 能迁移 | 换个变量后说清排名为什么变 |  |  |
| 能判错 | 对榜首材料写出「证据不足」并说出理由 |  |  |

**判定规则**：

- 两位读者都「通过」前四项 → 样板课成立，可按这个模式扩展其余篇章。
- 任一读者在「能进门」或「能复算」受阻 → **不扩展**，先改 04 的对应环节，再找人重试。
- 「能迁移 / 能判错」部分通过 → 记下卡住的原话，针对性补提示或例子。

## 五、把结果写回去

走查完成后，在 [CHANGELOG](更新记录.md) 的「第 7 批 · 04 样板课」条目下追加一段，格式：

```
外部读者走查（YYYY-MM-DD）：读者 A（零安装）/ 读者 B（基础）各 1 人。
- 能进门：A 通过 / B 通过（原话：…）
- 能复算：…；能迁移：…；能判错：…
- 首个卡点：…（第 X 环节，「……」这句）
- 结论：样板成立 / 需改后再测（具体改什么）
```

**不要把模拟走查、无头浏览器点检冒充外部读者结果**——机器能验证「页面能打开、搜索有结果」，不能验证「人能不能学会」。两者分开记录。
