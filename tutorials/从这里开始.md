## 先做一道证据题

招聘方问林澈做过什么。你只拿到下面三条材料。先写一句你愿意替他确认的话，再打开答案核对。

| 卡片 | 内容 |
| --- | --- |
| A | 「用 Python 做过课程项目」 |
| B | 「收藏了 Kubernetes 教程」 |
| C | 「课程项目只在本机演示」 |

目标岗位的描述写着：**要求 Python 经验；有 Kubernetes 上线经验者优先。**

先自己想一想，把答案写在纸上或心里：

1. 哪张卡能支持「林澈用过 Python」？能不能进一步说「他很熟练」？
2. 哪张卡能支持「林澈有 Kubernetes 上线经验」？
3. 如果关于某项要求一张支持的卡都没有，应该怎么写？

<details>
<summary>点开看参考答案与讲解</summary>

**1. 能支持「用过 Python」的是 A，但不能说「很熟练」。**
「做过课程项目」说明有过这件事，这是准确的；「熟练」是程度判断，需要更多、更强的证据（比如独立完成、用于实际项目、能讲清细节）。把「做过」直接说成「熟练」，就是超出证据下结论。

**2. 没有一张卡能证明「Kubernetes 生产上线经验」。**
B 是「收藏了教程」——这只说明他感兴趣，不等于学过，更不等于上线过。C 是「只在本机演示」——按**现有材料**，只能确认他在本机做过，无法证明他做过生产部署（注意用词：是「材料无法证明」，不是断言他「一定没做过」，也许有材料没放进来看）。岗位描述里写了 Kubernetes，那是**岗位的要求**，不是林澈的经历；把要求当成候选人的能力，是最常见的一种误判。

**3. 写「证据不足」。**
找不到依据就如实说没有依据。这正是 CareerLens 的核心规矩：**结论必须落到证据，缺证据就报缺口，不把推测写成经历。**

</details>

**常见误判**（看看你有没有踩中）：

- 把「收藏 / 点赞 / 关注」当成「掌握技能」——它们只是兴趣线索。
- 把「岗位要求」当成「候选人经历」——招聘方想要什么，不代表应聘者已经会什么。
- 把「做过」直接说成「熟练」——程度和数量需要独立证据。

## 两条学习路线

你想怎么学，取决于你现在会什么。两条路最后汇合到同一套核心内容。

### A 轨｜零基础

适合：从没写过代码，或分不清 Agent、提示词、RAG、向量检索是什么。

**默认下一步：只用浏览器做[00-1](00-foundations/00-1-Agent是什么.md)，做完看关卡产物能否交出。** 四篇按顺序走，不装软件、不登录、不碰终端。

| 阶段 0 篇目 | 做完要交出的产物（自测能否独立写出） |
| --- | --- |
| [00-1 Agent 是什么](00-foundations/00-1-Agent是什么.md) | 把一个问题拆成「目标 / 可用工具 / 约束」三步，并说出 CareerLens 为什么算「被约束的 Agent」。 |
| [00-2 提示词与证据](00-foundations/00-2-提示词与证据.md) | 给两段回答各标出支持它的卡片；找不到就写「证据不足」，不把「说得顺」当对。 |
| [00-3 RAG 与检索](00-foundations/00-3-RAG与检索.md) | 说出关键词匹配和语义匹配各适合什么，能把两条线索合成一次检索。 |
| [00-4 数据模型](00-foundations/00-4-数据模型大白话.md) | 把打乱的卡片排成「证据→画像→匹配→缺口→计划→报告」，并从报告编号指回原文。 |

1. 四篇全部交出上表的产物，就算过了阶段 0；每篇约 5–15 分钟（`00-1` 因为要讲清三个角色稍长）。
2. 想亲手跑时，再按你的操作系统做[本机准备](#什么时候需要安装软件)。
3. **过了阶段 0 的默认下一步**：跑通[第 01 篇](01-第一次跑起来.md)，在工作台走一遍完整流程。
4. 有兴趣再往下学实现原理。

设备不允许装软件？走[静态观察路线](静态观察路线.md)也能学懂原理，但那算「理解演示」，不算「本机跑通」。

### B 轨｜有基础

适合：会用终端、装过 Docker，或直接想看实现。

**默认下一步：从[第 01 篇](01-第一次跑起来.md)把服务跑起来**，再按你的目标选：

- 已会 Docker Compose 且跑通 Demo：直接进[第 04 篇样板课](04-检索Agent.md)，它是「预测→改变量→排错→迁移」的完整样例。
- 想按模块读：数据与解析（02–03）、检索与 Wiki（04–05）、后台任务与工程化（06–08）。
- 只想理解、暂时不装软件：仍可先做[第一题](#先做一道证据题)和阶段 0 的浏览器版。

## 阶段成果

每阶段结束都有「做到什么算过关」。入口只链接已经能读的内容，计划中的篇章会标明，不会给你坏链。

| 阶段 | 过关时你能做到 |
| --- | --- |
| 0 · 看得懂 | 不看答案，能从材料里指出一条支持证据和一条不能支持的证据，找不到依据时写「证据不足」。 |
| 1 · 跑得通 | 用工作台导入合成资料、完成一次岗位分析，找到一个有证据支持的匹配和一个缺口，并指出引用原文。 |
| 2 · 建地基 | 同一用户导入同一份文字两次，核对证据 ID 被复用；能指出来源与位置。 |
| 3 · 有智能 | 用同一个问题比较检索模式，追到一条原始证据；能说明为什么某条候选虽相关但应舍弃。 |
| 4 · 会验收 | 重复提交得到同一任务 ID，刷新后找回同一任务与进度；分清启动、迁移与 Worker 的状态。 |
| 5 · 会进阶 | 提交一页带引用、可复查的小项目；说清 Demo 和开发集成绩不代表生产准确率。 |

阶段 0 四篇已发布，从 [00-1](00-foundations/00-1-Agent是什么.md) 开始，按顺序读完约 1 小时，全程不用装软件。随时查[术语表](术语表.md)。

## 什么时候需要安装软件

**只有当你想亲手运行时才需要装。** 只想理解原理、做纸面练习，浏览这个页面就够了。

- 本机跑 Demo：需要 Docker Desktop / Docker Engine，**不需要**在电脑上另装 Python 或 Node.js，也**不需要** API Key、GPU 或真实个人资料。
- 想写脚本练习或做开发：再按系统补装 Python，见 [Python 选做准备](setup/Python准备.md)。
- 买不起或没有权限装软件：[静态观察路线](静态观察路线.md)用截图和预录响应学同样的原理。

安装步骤、命令逐行解释、按系统的差异，都在[第 01 篇的本机准备](01-第一次跑起来.md#步骤-1-本机准备)里。

## 遇到问题怎么求助

先按 [FAQ](常见问题.md) 自查——每项都按「看到什么 → 怎么确认 → 怎么恢复」写好了。

还解决不了，提 Issue 时请带上：

```text
1. 你正在读的篇名和卡在第几步
2. 你的操作系统和版本（Windows 11 / macOS 14 …）
3. 你执行的完整命令
4. 预期输出和实际输出（原样贴，不要只写「报错了」）
5. 你是否改过配置、用的是不是默认 Demo
```

**请遮掉密钥、账号、真实简历和任何个人资料再发。** 不要把真实数据贴到 Issue 或聊天窗口。
