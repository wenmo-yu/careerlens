# 动手准备 · 找对终端、Python 和练习数据

你在第 01 篇操作的是工作台。接下来会亲手改一个 Python 函数，再用测试检查改动。先用 10–15 分钟验清：你打开的是哪个目录，这个终端会用哪个 Python，浏览器当前在访问哪一份数据。

想只读原理，可以直接看[最小证据助手](../01-agent-design/入门练习-从零写证据助手.md)的输入和输出。第一次使用 Python，先完成[安装与第一行代码](Python准备.md)，再回来继续。

## 先在编辑器和终端找到同一个目录

用文件管理器打开解压后的文件夹。里面应能看到 `docker-compose.yml`、`backend` 和 `tutorials`。这个位置叫**项目根目录**。在编辑器用「打开文件夹」打开它。终端也进入这个路径，路径含空格时保留双引号。

```powershell
# Windows PowerShell，换成实际路径
Set-Location "D:\work\careerlens"
Get-Location
Get-Item docker-compose.yml
```

```bash
# macOS / Linux，换成实际路径
cd "$HOME/Downloads/careerlens-main"
pwd
ls docker-compose.yml
```

能列出文件后，试着在编辑器中打开 `tutorials/01-agent-design/README.md`。文件夹路径从项目根开始算。后面终端打印的是以盘符或 `/` 开头的绝对路径，可以直接在编辑器里用「打开文件」定位。

## 给源码练习准备一套 Python

虚拟环境是一套单独安装的 Python 包。下面的命令把后端、FastAPI、LangGraph 和测试工具装进 `.cache/agent-venv`。第三、四章、MCP、评测和结课可以用同一套。已有能执行 `import app` 和 `pytest` 的 CareerLens 开发环境时，激活已有环境即可。

```powershell
# Windows，在项目根。若 py 可用，也可用 py -3 -m venv .cache/agent-venv
python -m venv .cache/agent-venv
.\.cache\agent-venv\Scripts\Activate.ps1
python -m pip install -e "./backend[dev]"
python -m pytest --version
python -c "import sys, app; print(sys.executable)"
```

```bash
# macOS / Linux，在项目根
python3 -m venv .cache/agent-venv
source .cache/agent-venv/bin/activate
python -m pip install -e "./backend[dev]"
python -m pytest --version
python -c "import sys, app; print(sys.executable)"
```

打开第二个终端时，先进入项目根，再执行对应系统的**激活**命令。安装依赖只做一次。PowerShell 拒绝运行激活脚本时，可把后面命令开头的 `python` 替换成 `.\.cache\agent-venv\Scripts\python.exe`，例如：

```powershell
.\.cache\agent-venv\Scripts\python.exe -m pytest --version
```

如果你进入了 `backend` 目录才运行命令，显式解释器路径前加一层父目录，或者先回到项目根激活环境。遇到 `No module named pytest` 或 `No module named app`，先用 `python -c "import sys; print(sys.executable)"` 核对解释器，再看依赖安装命令是否成功。

## 先让一个检查失败，再修过它

在项目根的 `.cache` 内新建 `hello_check.py`。看不到这个文件夹时先建一个。用编辑器写入并保存：

```python
def evidence_label(title):
    return title


assert evidence_label("  Python 练习  ") == "Python 练习"
print("检查通过")
```

运行 `python .cache/hello_check.py`。末尾的 `AssertionError` 指向 `assert`，意思是实际值和期望值不同。只改 `return`：用 `title.strip()` 去掉两头的空格。保存后原样重跑，应该看到 `检查通过`。请留下你改的那一行。接下来的 `practice.py open` 和 `check` 也按这个顺序：打开提示、做一小改、看失败落在哪、原样重跑。

## 核对环境与编号

本课把 **账号** 写作 `user_id`，供服务确定资料属于哪个教学用户。Swagger 是一个能发 HTTP 请求的网页。浏览器地址里的 **端口**（例如 `8031`）用来选中正在听请求的服务。

| 环境 | Swagger / 界面 | 本课样例使用 |
| --- | --- | --- |
| 第 01 篇的 Compose | `http://localhost:8000/docs`，工作台 `http://localhost:3000/workspace` | 工作台初始 `demo-user`。第 01 篇的 Swagger 与第 06 篇主线示例用 `learner` |
| 第三章 Agent 副本 | `http://127.0.0.1:8030/docs` | `.cache/agent-practice/backend`，综合课用 `agent-lesson` |
| 第四章知识库副本 | `http://127.0.0.1:8031/docs` | `.cache/knowledge-practice/backend`，用 `kb-study` |
| 06、07、07-A 的主线 | 返回 Compose `8000`；MCP 另在 `8001/mcp` | 06 用 `learner`，07 准备 `learner-plan`，07-A 用同一位报告用户 |

两份练习副本各有独立的 SQLite 文件。下面是每次换环境前的检查卡：

1. **先看地址。** 我现在是在工作台、Agent 副本还是知识库副本？
2. **再看账号。** 请求体、列表查询和路径里的 `user_id` 是不是同一个值？
3. **最后看编号。** `evidence_id` 用于原文，`thread_id` 用于会话，`run_id` 用于任务，`job_analysis_id` 用于岗位快照，`report_id` 用于报告。跨库时保留笔记和合成材料，在新服务重新取得 ID。

新开练习 API 后先看对应地址的 `/health/live`，再开 `/docs`。Compose 则按第 01 篇验证 `/health/ready`。Worker 在第二个终端运行，它和 API 必须用同一个练习副本。服务终端停止后，在相同目录和解释器下重跑命令会继续读取原来的 SQLite 文件。
