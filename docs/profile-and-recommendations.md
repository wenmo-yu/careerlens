# 画像、推荐与自陈探索（HY4）

这篇文档说明 HY4 增强的行为边界：哪些数字有证据支撑，哪些只是用户自陈，哪些是本地教学模板。实现以当前源码为准，本文不承诺真实市场准确率。

跟做可从[导入与可回查画像](../tutorials/10-导入与可回查画像.md)开始，再用同一份资料做[岗位对比与学习计划](../tutorials/11-岗位对比与学习计划.md)。

## 1. 导入结果卡

同步上传响应和后台上传任务的 `result` 提供下面几类字段。工作台任务完成后点「打开结果」，可以通过导入结果卡查看这些统计和原文。也可用 Run ID 到 Swagger 查看任务结果，再按证据编号读回原文。

- **`readable_count`** 统计有正文且没有待 OCR 标记的解析块。`count` 统计响应带回的 Evidence。
- **`ocr_pending_count`** 统计需要 OCR 的扫描页，`warnings` 补充原因。
- **证据编号** 可从同步上传的 `items` 或任务的 `result.evidence_ids` 查得。重复上传同一文件时，比对证据编号和来源编号。连接器另返回 `created_count`、`skipped_count` 和 `duplicate_count`。

关键口径：**任务成功不等于读出了文字**。全扫描 PDF 可能入库成功但 Evidence 为 0，解析状态是 `partial`。旧 `.doc` 返回 422 并提示另存为 `.docx` 或导出带文字层 PDF。

## 2. 证据类型统一

以下两种输入会得到同一个判断：

- 用户粘贴「我收藏了一份 Kubernetes 教程」；
- 浏览器扩展采集的一条「收藏」记录。

二者都标 `claim_strength = "preference_signal"`，抽取器不会把它们升级成 skill / experience / target_role。含明确执行动作的语句（如「在本地 Kubernetes 集群部署 API 并通过探针」）按自报事实处理，仍需用户核对原文。

## 3. 画像概览与 Agent 清单

`GET /api/v1/profiles/{user_id}/overview` 返回只读统计：独立证据数、来源文档数、可读证据数、条目数、已确认条目、覆盖度（有证据 / 弱证据 / 无证据）和生成时间。口径写在返回的 `methodology` 字段里。

- 独立证据按 Evidence 行计；同一文本来自多个来源仍只算一条；
- 覆盖度：有有效证据且非弱证据为 supported；仅一条证据或启发式可信度 < 0.7 为 weak；无有效证据为 missing；
- 不要拿 `ProfileItem.id` 当长期锚点：`rebuild_profile()` 会全删重写，id 每次都变。用 `(category, name)` 加 `evidence_ids` 作为引用。

`GET /api/v1/profiles/{user_id}/agent-manifest` 给 AI 客户端列能力：可查询的端点、所需 scope、证据策略，以及 `writable_policy: agent_can_propose_only`。Agent 可以读事实、解释缺口、生成草案；不能静默写长期画像，写入仍走「提案 → 用户确认」流程。

## 4. 职业方向与课程推荐

`roles.json` 与 `courses.json` 是随仓库发布的本地教学模板：

- 方向模板含任务、必需/加分技能、入门证据、成长路径和 `source_note`；
- 课程含技能、级别、格式、提供者、课时、成本、先修、URL、许可、语言、最近核对时间和验收方式；
- 加载时校验重复 ID、悬空先修、URL 协议白名单和日期格式；坏数据报错而不是静默产出空推荐。

推荐按确定性规则运行。方向先按可回查技能覆盖的必需项比例排序，同分再按加分项命中数。课程按技能找目录项，返回建议课时和先修关系，供读者安排时间。方向推荐的理由可以回到 Evidence。人格测评结果、点赞收藏和自填标签都不参与这个排序。

注意：这些是教学模板，不代表招聘市场统计；课程只保留 URL 与元数据，运行时不抓取外部内容。

## 5. 多 JD 对比与学习看板

用户可以保留每份 JD 的原句和备注。`GET /api/v1/saved-jobs/compare` 返回最近三份保存记录，可据此并排找共同要求。分别运行岗位分析，才能得到每份 JD 的匹配分和缺口。

学习看板把现有 `learning_path` 按周排布，加入资源、验收方式和进度状态（待开始 / 进行中 / 待提交作品 / 已核对 / 暂停）。进度只能关联当前用户已存在的 Evidence；作品提交不会自动新增能力事实。

## 6. 自陈测评的边界

测评分三层：

| 层 | 内容 | 能否进事实画像 | 是否影响匹配分 |
| --- | --- | --- | --- |
| L1 事实层 | 技能、经历、项目 | 是 | 是 |
| L2 自报偏好 | 兴趣、目标角色、约束 | 是，但标 `self_report` | 解释用，不计分 |
| L3 测评探索 | 工作偏好、活动兴趣、自填标签 | 单独存储 | 否 |

顺序是「先问真实选择，再做可选测验」：

1. 工作方式快测（项目自写 5 题，可跳过）；
2. 完整量表（都可跳过、可重测）：
   - `work_style_4d`：32 题四维工作偏好，输出百分比与偏好组合，接近中点时明确提示；
   - `riasec_interest`：48 题活动兴趣，输出六维分数、前三代码、一致性、分化度与本地目录方向线索；
   - `big_five_20`：20 题大五短版，含反向题，输出五维分档与工作风格提示；
3. INTP 等人格标签仍可由用户自愿自填与删除，只作反思与对话提示。

题目全部为本项目自写；`big_five_20` 只参照公有领域 IPIP 的构念，不复制 MBTI®、OEJTS（CC BY-NC-SA）或 O*NET Interest Profiler（CC BY-ND）的题目或译文。逐项许可比对与计分规则见[测评题库与许可](assessments.md)。

测评结果必须显式同意后保存，可重做、导出、删除；至少回答 80% 题目才计分，未答项不插补。画像概览只回显每个量表最近一次的代码与时间，明确标注「不是能力事实」。删除后相关报告标 stale。自陈数据进入隐私导出与账号删除清单。

## 7. 多子 Agent 的并发边界

运行时保持「每用户串行、全局有界并发、单事务提交」：

- `Coordinator` 预算默认 2，可参数化；现有四个 specialist 之间有数据依赖，仍按顺序派发；
- 新增的三个 specialist 只返回草稿，不写业务表；
- `event()` 用 `UPDATE ... RETURNING` 原子分配 `RunEvent.seq`；
- 并行入口的测试使用两个无依赖的只读角色。任一分支失败时，`delegate_many()` 向调用方抛出异常。默认岗位、Wiki 与报告操作仍按各自依赖顺序派发；
- `delegate()` 失败会补发 `step.failed`，避免 SSE 停在 running；
- Demo provider 没有网络延迟，测不出提速；只有 fake provider 或真实 provider 的对照数据显示 P95 下降且失败率不升，才能说「提速」。

## 8. 补充轮：导入来源、画像模式与时间线

### 8.1 导入来源注册表

`GET /api/v1/connectors/registry` 列出系统**真实支持**的来源，按 `auth_level` 分组：

- **A 用户导出/粘贴**：文本直录、PDF/Word .docx/表格、HTML 另存为与 ZIP 导出包、图片音视频、B站/微博导出、公开链接证据卡；
- **B 当前页采集**：浏览器扩展手动勾选的可见内容；
- **T 自备只读令牌**：用自己的 GitHub 令牌读取选定仓库的元数据和 README；
- **C 需平台授权**：`official_oauth` 明确标为 `available: false`，没有端点，不声称可用。

HTML 与 ZIP 都用 Python 标准库解析：**不联网、不登录、不需要 bs4/lxml**。HTML 跳过 script/style，ZIP 拒绝路径穿越与超大成员。公开链接证据卡只保存用户填写的 URL、标题和说明，后端**从不访问该链接**，也不证明账号归属；链接带 query token 时会被清掉。

### 8.2 画像模式与模块开关

`GET/PUT /api/v1/profiles/{user_id}/view-preferences` 保存五种模式：求职冲刺、转行探索、能力盘点、学习计划、极简模式；并可选择十个显示模块（技能矩阵、经历时间线、兴趣线索、目标角色、证据健康度、工作价值观、约束条件、自定义维度、学习进度、面试故事库）。

模式与模块开关作为显示偏好保存在 `user_constraints`。可以从相同端点读回设置，画像条目、引用和岗位匹配分仍使用各自的数据。

能力证据卡把每条画像拆成「动作 + 环境 + 证据 + 状态」，状态区分已确认/证据支持/自报/待补证据。

面试故事保存在 `ProfileExtension`，新记录的键由 `story:` 和独立故事 ID 组成。同一用户能保留多条同名故事。故事引用当前用户的 Evidence 时标记为「证据支持」，留空时标为待补。引用另一位用户的 Evidence 会被拒绝。

### 8.3 浏览器采集扩展

当前页采集支持 B站、微博、抖音、掘金、CSDN、知乎、小红书、GitHub。扩展仍只读取当前标签页可见 DOM，不读 Cookie、不自动翻页、不后台轮询。

- `published / authored / merged` → `self_reported_published`（用户自报贡献，未证明账号归属）；
- `liked / favorite / following` → `preference_signal`（仅兴趣线索，不进技能事实）。

新增平台只放宽域名白名单和 URL 模式，**没有**新增网络请求能力。页面结构会变，采集失败时给用户明确提示，不静默产出证据。

### 8.4 Run 步骤时间线

任务中心把 `RunEvent` 渲染成带序号、事件类型、耗时（`duration_ms`）、引用数和 fencing 代次的步骤时间线。失败的 specialist 现在会发出 `step.failed` 终态，不再停在 running。
