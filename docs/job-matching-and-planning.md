# 岗位评分与学习路线

## 如何算分

| 项目 | 规则 |
| --- | --- |
| 岗位优先级 | 必需权重 1；加分权重 0.5。目录规则按分句和显式标题识别，不将相邻加分关键词扩散到前一条要求。 |
| 证据支持 | 有当前用户的有效证据且画像等级 ≥ 3 为 strong（系数 1）；证据有效但等级较低为 partial（0.65）；没有有效证据为 gap（0）。 |
| 匹配分 | 权重乘以支持系数后求和，再除以总权重，乘以 100，保留一位小数。例：必需 Python strong、必需 Docker gap、加分 PostgreSQL partial：`(1 + 0 + 0.5 × 0.65) / 2.5 × 100 = 53.0%`。 |
| 投递建议 | 有必需缺口时，即使总分 ≥ 70，也优先提示补齐必需缺口。没有必需缺口时才按分数给建议。 |

规则只算识别到的技术要求，不代表录用概率。等级和置信度是内部启发式指标。模型可以补充有逐字引文的长尾要求，不直接改写分数。复杂句、隐含要求和非技术要求仍需人工核对。

## 如何排计划

- 必需缺口 → 必需弱项 → 加分缺口 → 加分弱项，最多展示四个阶段；后续缺口仍在逐项匹配列表中。
- 无基础的必需项估算 18 小时，加分项 10 小时。已有能力按等级估算：Level 1 为 12 小时，Level 2 为 9 小时。
- 每阶段至少一周，周数为 `ceil(预计小时 / 每周可投入小时)`，阶段串行，不挪用前一阶段的剩余时间。例如每周 6 小时的 18 小时必需缺口占第 1–3 周，9 小时必需弱项占第 4–5 周。
- 这是一份可复核的实践估算，不是课程或就业承诺。修改每周投入时间后重新分析 JD。

已保存的岗位分析仍可读取作为历史快照。删除证据或调整画像后，报告与显式引用该岗位分析的对话会重新核验匹配结果；如不一致或使用旧版评分规则，返回 `409`，请重新分析 JD。历史报告不覆盖。
