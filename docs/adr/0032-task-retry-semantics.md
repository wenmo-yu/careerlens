# ADR 0032：任务重跑是"新增一棵树"，不是"改旧记录"

- 状态：Accepted
- 日期：2026-11-29
- 相关：`backend/app/runtime/agent/multi.py`、`POST /api/v1/agent/tasks/{id}/retry`

## 决定

重跑失败任务时，**新建一个团队**（父 + 子任务、各自的会话与 Run），旧团队的状态、结果与错误一字不改。

- 叶子任务：用它自己的 `role` 与 `input` 重建一个单子任务团队。
- 协调者（父任务）：用它现有子任务的 `role` + `input` 重建，因为父任务本身不持有提示词。
- 标题加前缀"重跑："，便于在列表里区分。
- 角色去重：`create_team` 要求角色唯一，重复的角色会被裁掉而不是整体失败。
- 跨用户或任务不存在一律 `409`，不泄漏存在性。

## 为什么不做"原地重试"

原地重试会覆盖 `run_id`、`result`、`error` 与预算累计，等于让历史不可信。M6 的结果投影依赖"每个 attempt 有自己的记录"，而审批账本按 run 幂等；改旧行会让审计链断裂。

## 边界

- 没有"重跑失败子任务并合并回原团队"的语义：新团队是独立的，父任务投影不会回填旧团队。
- 没有重试次数上限与自动重试；调用方决定。
- 预算不继承：新团队从默认预算开始。
- UI 的取消按钮走 `cancel_task_tree`（级联子任务），重跑按钮走本接口。
