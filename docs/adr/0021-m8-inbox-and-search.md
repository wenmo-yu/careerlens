# ADR 0021：M8 应用内通知与任务搜索

- 状态：Accepted（派生通知与只读搜索已实现；系统唤醒与通知投递未做）
- 日期：2026-11-28
- 相关契约：[`agent-inbox-v1.json`](../../contracts/agent-inbox-v1.json)
- 相关代码：`backend/app/runtime/agent/inbox.py`、`backend/app/api/routes/agent_inbox.py`

## 决定

通知中心**不新增第二套事实源**。读取时从已有的持久事实派生：待审批（`agent_approvals`）、失败/中断的 agent Run（`agent_runs`）、失败的子任务（`agent_tasks`）、跳过/失败的计划 occurrence（`agent_schedule_occurrences`）。每条通知用稳定的 `fact_key` 标识，只有用户的"已读"回执落库（`agent_notification_reads`），标记已读是幂等的。

任务搜索是只读的，严格限定当前用户，跨会话、任务、角色和计划做有界检索（上限 30 条/类）。它不返回他人内容，也不通过计数差异暴露跨租户存在性。

通知中心**没有任何外部投递**：不发邮件、webhook、推送或短信。它是应用内的待办视图，避免 V4 禁止的"任意外发"。

## 为什么这样设计

- 派生而非物化，避免通知与 Run/审批/任务状态漂移，也不需要额外的写入路径和一致性负担。
- 只持久化最小的用户状态（已读），把事实权威留在原表，符合"业务库唯一事实源"。
- 搜索复用现有表与用户隔离中间件，不引入索引副本或缓存层。

## 验证

- 待审批、失败 Run、失败任务、跳过 occurrence 都能出现在收件箱且 `read=false`。
- 标记已读后 `read=true`，重复标记返回 `added=0`。
- 跨用户查询收件箱/搜索都只能看到自己的事实。
- 搜索空/超长查询返回 422；结果按类型有界。
- 迁移 `f8a9b0c1d2e3` 建立已读回执表，head 一致。

## 未做与边界

- 没有系统级唤醒、开机自启、通知投递时机、DST/睡眠处理；这些需要真机验收。
- 没有 SSE 实时推送通知，UI 需主动刷新。
- 这是应用内状态视图，不是外部消息系统；不得据此声称"已支持通知送达"。

## 回滚

删除本 ADR、契约、`agent_notification_reads` 表及迁移、收件箱/搜索 API 与服务即可；既有事实表不受影响。
