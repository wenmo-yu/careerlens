# ADR 0028：Agent 工作台的实时事件与计划/通知视图

- 状态：Accepted（补充 ADR 0019；仍不是完整三栏桌面 UI）
- 日期：2026-11-28
- 相关代码：`frontend/app/agent/page.tsx`、`frontend/lib/api.ts`

## 背景

ADR 0019 的 `/agent` 只有轮询：提交一轮后只能等下一次刷新看消息，看不到 `run.*` 事件，也没有计划与通知视图。这让"Run 正在执行"和"Run 卡住了"在界面上无法区分。

## 决定

1. **实时事件**：提交成功后拿 `run.id`，用现有 `GET /runs/{id}/stream`（SSE，带 `Last-Event-ID`）订阅事件，最多保留最近 40 条，并显示终态。
2. **不建第二事实源**：事件流只用于"现在发生了什么"；消息、审批、计划、通知仍通过各自的持久接口读取，轮询保留，作为断线与丢帧的兜底。
3. **新增两个只读面板**：计划（名称/状态/策略/下次到期）与通知（标题/详情/已读状态，可一键全部已读）；再加一个只读检索面板（会话/任务/角色/计划四类计数与前几条）。
4. **断线语义**：SSE 断开只提示"事件流已结束，以数据库为准"，不把断线当成 Run 失败；`run.committed` 之后仍以消息/审批数据为准。

## 为什么不做 WebSocket / 前端事件库

后端已经有一条经过测试的 SSE 事件流与游标语义（`seq` + `Last-Event-ID`），再接一套 WebSocket 会引入第二套排序与重连规则。轮询 + SSE 的组合已经能覆盖"实时看进度、最终看事实"。

## 验证

- `pnpm lint`、`pnpm test`、`pnpm build`、`pnpm build:desktop` 通过，`/agent` 出现在主构建与静态导出路由中。
- 事件按 `seq` 追加，终态显示；断线提示不改变 Run 状态。
- 计划/通知/检索失败只显示错误，不影响会话与审批操作。

## 未做与边界

- 没有任务树/团队邮箱可视化、没有连接 epoch 与多会话并行看板。
- 没有窄窗口专门布局与键盘全流程（只在开关与按钮上保证焦点可见）。
- 没有通知投递（站内派生视图，不外发）。
